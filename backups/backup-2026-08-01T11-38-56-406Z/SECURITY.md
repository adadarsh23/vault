# Security Policy

## Supported Versions

Security fixes are applied to the latest version on the default branch.

## Reporting a Vulnerability

- Do not open public issues for security bugs.
- Report privately to project maintainers.
- Include: summary, impact, steps to reproduce, affected files/paths, and proof-of-concept (if safe).

## Response Process

- We acknowledge reports as quickly as possible.
- We validate, prioritize, and patch confirmed issues.
- We may request extra details for reproduction.

## Disclosure

Please allow time for a fix before public disclosure.

## Scope

In scope: authentication, authorization, secrets handling, data exposure, injection, and dependency vulnerabilities.
Out of scope: low-impact UI bugs, non-exploitable warnings, and social engineering.
